# AVITO ARBITRAGE AI

Система поиска, оценки и подготовки сделок на вторичном рынке по мастер-промпту
«AVITO ARBITRAGE AI v2.0»: массовый анализ объявлений → дубликаты → модель →
аналоги → неисправности → три стратегии восстановления → прибыль и риск →
рабочая таблица на 6 листов → решение пользователя → переговоры в пределах лимитов →
учёт фактических результатов.

> **Важно о данных.** Система не собирает объявления с Avito сама. У Avito нет
> публичного API для поиска чужих объявлений, сайт закрыт для автоматических агентов,
> а обход защиты и CAPTCHA запрещён (раздел 19). Объявления поступают двумя путями:
> страницы, которые вы сами сохранили в браузере (Ctrl+S), или выгрузка JSON/CSV.
> В `examples/test_listings.json` лежат **синтетические** тестовые данные — не
> предложения рынка, и в таблице они явно помечены.

## Быстрый старт

```bash
cd avito_arbitrage
pip install -r requirements.txt
cp config.example.yaml config.yaml                 # уже настроен на Тюмень; поправьте лимиты

# 1. Проверка на тестовых данных (раздел 23)
python examples/generate_test_listings.py
python -m arbitrage --config config.yaml campaign --input examples/test_listings.json

# 2. Реальная кампания по сохранённым страницам
python -m arbitrage --config config.yaml search-plan          # out/search_plan.csv со ссылками
#    откройте ссылки в своём браузере, сохраните страницы выдачи (Ctrl+S) в папку pages/
python -m arbitrage --config config.yaml campaign --input pages/
```

`out/avito_arbitrage.xlsx` открывается в Excel или импортируется в Google Sheets
(Файл → Импорт), формулы при этом сохраняются. Прямая выгрузка в Google Sheets:
`--google-sheet --share you@example.com` (нужны `pip install gspread` и ключ
сервисного аккаунта в `GOOGLE_SERVICE_ACCOUNT_JSON`).

## Сохранённые страницы Avito

1. `search-plan` создаёт CSV со ссылками поиска по Тюмени, ближним городам и всей России.
2. Откройте ссылку в своём браузере, при необходимости отсортируйте по цене и пролистайте.
3. Сохраните страницу: Ctrl+S, формат «Веб-страница полностью» (.html) или «одним файлом» (.mhtml).
4. Для лучших кандидатов сохраните и страницы самих объявлений — там полное описание,
   продавец и состояние. Повторный импорт дополнит запись, история цены сохранится.
5. `campaign --input pages/` разберёт все .html/.mhtml/.json/.csv в папке.

Из страницы поиска берутся ID, ссылка, город (из адреса), раздел, заголовок, цена,
фрагмент описания, адрес и дата. Из страницы объявления — также полное описание,
состояние и продавец; блок «похожие объявления» игнорируется. Разбор опирается на
устойчивые признаки (адрес объявления `…_<ID>`, микроразметка, знак ₽), а не на классы
вёрстки. **Парсер проверен на тестовых образцах, а не на живых страницах Avito**:
если первая реальная страница разберётся плохо, пришлите её — парсер подстроится.
Записи без цены или заголовка отклоняются с причиной, ничего не дописывается.

## Тюмень и другие города

Домашний город (`region: Тюмень`) — рынок перепродажи. Аналоги для оценки берутся из
Тюмени, если их хотя бы 4; иначе — из всех городов, с пониженной уверенностью и пометкой.
Для объявления из другого города логистика выбирается автоматически:

| Где продавец | Как забираем | Что учитывается |
|---|---|---|
| Тюмень | самовывоз по городу | `transport_cost` по габаритам |
| город из `pickup_distances_km` (≤ `max_pickup_km`) | поездка, если она не дороже доставки + `inspection_value` | дорога 2 × км × `travel_cost_per_km`, +1 день для дальних |
| остальные | доставка | `delivery_cost`, +`delivery_days`, риск +10, ещё +10 для неисправного, осмотр только при получении |
| крупногабарит вне зоны самовывоза | не возим | сделка пропускается |

Для доставки меняются проверки до покупки (оплата только на платформе, видео работы
до заказа, проверка в пункте выдачи) и текст сообщений продавцу. Расстояния в
`config.example.yaml` приблизительные — поправьте под свои маршруты.

## Рабочий цикл

| Шаг | Команда | Что происходит |
|---|---|---|
| Кампания | `campaign --input …` | Чтение, отбраковка записей без ссылки/цены, дубликаты, анализ, запись в БД, таблица, отчёт |
| Проверка пользователем | правка колонки «Статус пользователя» → `import-statuses out/campaign.xlsx` или `status APPROVED <ID…>` | APPROVED / WATCHLIST / REJECTED / NEEDS REVIEW |
| Разрешение на торг | `negotiate authorize --text "Давай, начинай переговоры по одобренным объявлениям"` | Принимается только эта фраза; в разрешение попадают одобренные на этот момент объявления |
| Первое сообщение | `negotiate prepare` | Перепроверка цены, пересчёт экономики, черновик. **Сообщение отправляете вы** |
| Отправка | `negotiate sent <ID>` | Вы подтверждаете, что отправили |
| Ответ продавца | `negotiate reply <ID> --text "…"` | Разбор позиции и цены, новые дефекты → пересчёт предела, следующий шаг и черновик |
| Сделка | `deal <ID> --status bought/repairing/listed/sold/written_off …` | Фактические цены и расходы, ошибки прогноза, калибровка |
| Отчёт | `report` | Итоги кампании и переговоров (раздел 22) |
| План поиска | `search-plan [--cities Тюмень Курган Россия]` | CSV многопроходного поиска со ссылками для ручного открытия (раздел 5) |
| Telegram | `telegram` | Управление из чата (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_ID`) |

Агент **никогда** не покупает, не платит и не вносит предоплату, не превышает
максимальную цену и не раскрывает её продавцу. Он также не утверждает, что отправил
сообщение, и прекращает контакт, если продавец просит больше не писать.
`auto_purchase: true` в настройках игнорируется.

## Формат объявлений (JSON или CSV, если не сохранённые страницы)

Обязательные поля: `url`, `title`, `price`. Остальные заполняются, если известны:
`description`, `category` (код из `arbitrage/categories.py` или название категории Avito),
`brand`, `model`, `configuration`, `city`, `district`, `published_at`, `seller_id`,
`seller_name`, `condition`, `photos_count`, `search_query`, `is_synthetic`.
ID берётся из ссылки Avito (`…_1234567890`). Повторно загруженное объявление
обновляет запись, история цен сохраняется.

Аналоги (`--comps`): `title`, `price`, `condition` (исправен/неисправен), по желанию `category`, `city`, `source`.

## Как считается экономика

Для каждого объявления строятся стратегии: покупка исправного, **A** самостоятельный
ремонт, **B** сервис, **C** продажа без ремонта или на запчасти. Каждая считается в трёх
сценариях: консервативном, базовом и оптимистичном.

* **Рынок.** Используются медиана и квартили цен аналогов той же модели, выбросы
  отсекаются по IQR. Цена сделки ≈ 92% цены выставления. Консервативная цена берётся
  по нижнему квартилю, с дисконтом при слабой оценке. Если точных аналогов нет,
  используется семейство модели с пониженной уверенностью.
* **Полная себестоимость** = покупка + диагностика + детали + работа + транспорт +
  прочее + резерв + продажа.
* **Резерв** включает перерасход ремонта (A 20% / B 30% / C 50% в консервативном
  сценарии), возвраты и скрытые дефекты (3%), а также риск неудачного ремонта:
  `(1 − p) × (прибыль при успехе − прибыль при неудаче)`. Поэтому
  «цена перепродажи − полная себестоимость» равна ожидаемой прибыли, и формулы в таблице честные.
* **Максимальная цена покупки** = консервативная цена − все прочие расходы − требуемая прибыль.
  Дополнительно её ограничивают требование ROI, лимит одной покупки и свободный капитал.
  Для DIY учитывается стоимость вашего времени.
* **Стресс-тесты (раздел 11):** ремонт дороже на 50%, дополнительная неисправность,
  продажа на 15% дешевле, продажа вдвое дольше, неудачный ремонт. Сделка исключается,
  если возможная потеря больше 25% капитала при заметной вероятности неудачи.
* **Рейтинг 0–100** складывается из прибыли (25), надёжности оценки (20), ликвидности (20),
  запаса прочности (15), проверяемости (10) и оборота (10). **Риск 0–100** считается отдельно.
  Критический риск ограничивает рейтинг 20, подозрительно низкая цена — 50, риск ≥ 60 — 69.

## Справочник неисправностей

`arbitrage/data/repair_kb.yaml` содержит симптомы (фразы и учёт отрицаний: «экран не
разбит» дефектом не считается), красные флаги (iCloud/FRP, IMEI, предоплата, копия,
сомнительное происхождение), классы A/B/C, гипотезы причин, стоимость DIY и сервиса,
вероятность успеха и проверки до покупки.

**Суммы в справочнике — ориентировочные значения по умолчанию, а не цены конкретных
сервисов.** Уточните их под свой город. После первых сделок `learning.py`
скорректирует оценки рынка, ремонта и сроков по фактическим результатам.
Диагноз по тексту всегда остаётся гипотезой. Работа с микроволновками (высокое
напряжение) и холодильным контуром в DIY не предлагается.

## LLM-анализ (необязательно)

`llm_enabled: true`, `pip install anthropic`, `ANTHROPIC_API_KEY`, затем `campaign --llm`.
В Claude передаются только неоднозначные объявления: модель не распознана или
неисправность не уточнена. Действуют лимит вызовов на кампанию и кэш по содержимому
в БД. Ответ — структурированный JSON по фиксированному списку кодов симптомов и рисков.

## Хранилище

По умолчанию данные хранятся в SQLite (`data/arbitrage.db`). Для PostgreSQL задайте
`DATABASE_URL=postgresql+psycopg://…`. В базе лежат объявления, история цен, история
анализов, решения пользователя, переговоры и сообщения, сделки, журнал событий и кэш
LLM. Пропавшее из выгрузки объявление помечается `unavailable`, а не «продано»
(`--full-recheck`).

## Структура

```
arbitrage/
  config.py        настройки (раздел 3)
  categories.py    категории, ликвидность, габариты
  identify.py      бренд и модель → ключ для аналогов
  defects.py       симптомы, флаги, профили ремонта (+ data/repair_kb.yaml)
  market.py        оценка по аналогам
  economics.py     стратегии, сценарии, предельная цена, стресс-тесты, цены торга
  scoring.py       ликвидность, риск, рейтинг
  analyzer.py      полный анализ и рекомендация
  dedup.py         дубликаты и повторные публикации
  sources.py       JSON/CSV/папки и точка подключения разрешённого источника Avito
  html_import.py   разбор страниц Avito, сохранённых пользователем (.html/.mhtml)
  geo.py           домашний город, самовывоз, доставка, ссылки поиска
  storage.py       SQLAlchemy: SQLite / PostgreSQL
  pipeline.py      кампания
  export/          6 листов → XLSX и Google Sheets
  negotiation.py   переговоры с подтверждениями пользователя
  learning.py      фактические сделки и калибровка
  llm.py           Claude API для неоднозначных описаний
  telegram_bot.py  управление из Telegram
  report.py        итоговые отчёты
```
